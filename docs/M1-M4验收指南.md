# MiniCode M1–M4 人工验收指南

本文只解决一件事：让你能亲自判断每个阶段是否真的通过。不要因为命令没有报错就勾选通过；必须同时满足对应的功能证据。

## 0. 一次性准备

在项目根目录打开 PowerShell：

```powershell
cd D:\000Study\agentProgram
Copy-Item .env.example .env   # 已存在则不要覆盖
notepad .env
```

至少填写：

```dotenv
DEEPSEEK_API_KEY=你的真实Key
MINICODE_BASE_URL=https://api.deepseek.com
MINICODE_MODEL=deepseek-v4-flash
```

Key 只放 `.env`。所有阶段开始前先运行：

```powershell
.\start.cmd test
```

当前基线应显示 `Ran 37 tests` 和 `OK`。若失败，先不要做人工验收。

## 1. M1：能可靠修改代码

### 怎么运行

```powershell
.\start.cmd demo
```

脚本会复制一个一次性除零 Bug 仓库，不会修改模板。记下输出中的 `Disposable demo workspace` 和 `Run ID`。

### 必须看到的证据

1. Agent 先读取实现和测试，再建立多步骤计划；
2. 使用 `apply_patch` 修改 `calculator.py`，不能只在回答里描述；
3. 至少运行一次测试；最终显示测试通过；
4. 调用 `git_diff`，能看到实际 Diff；
5. `finish_task` 完成协议通过，最终状态为 completed；
6. 最终总结包含修改文件、测试证据和剩余风险。

### 判定

- 全部满足：M1 PASS；
- 测试通过但没有 Diff/完成协议：FAIL；
- Agent 说“已修复”但文件没变：FAIL；
- 达到步骤预算或 Provider 报错：本次未通过，可重试但要保留失败 Trace。

可复核：

```powershell
.\start.cmd replay <run_id> "<Disposable demo workspace>"
```

## 2. M2：上下文压缩、Checkpoint 与恢复

### 怎么运行

```powershell
.\start.cmd demo2
```

这个 Demo 会故意用较小上下文和步骤预算暂停。记下 workspace 与 Run ID：

```powershell
.\start.cmd status <run_id> "<Demo workspace>"
.\start.cmd resume <run_id> "<Demo workspace>"
.\start.cmd replay <run_id> "<Demo workspace>"
```

### 必须看到的证据

1. 第一次运行以 `budget_exhausted` 暂停，而不是伪装完成；
2. `.mini-code/runs/<run_id>/checkpoints/` 中存在多个 JSON checkpoint；
3. `status` 能显示步骤、计划和修改文件；
4. `resume` 使用同一 Run ID，从后续步骤继续；
5. 已成功完成的 Patch 不重复应用；
6. 恢复后测试和完成协议通过；
7. Replay 中能看到 `context_compacted`、`checkpoint_saved`、`run_resumed` 中实际发生的事件。

### 冲突保护（建议额外验收）

再建一个 `demo2`，暂停后手动修改其 `calculator.py`，再执行 resume。预期返回 `Resume conflict`、退出码 3，且 Agent 不继续 Patch。这个冲突用 Demo 副本测试，不要破坏准备正常恢复的唯一副本。

## 3. M3：安全、Replay 与量化评测

### 离线验收

```powershell
.\start.cmd security
```

必须显示 `15/15 blocked`，并生成 `.mini-code/security/audit-*.json`。这只证明当前 15 个版本化探针通过，不代表系统拥有 OS 沙箱。

### 故障恢复验收

对可信的测试仓库运行：

```powershell
.\.venv\Scripts\python.exe run_mini_code.py run `
  "修复 Bug，运行测试并查看 Diff" `
  --workspace D:\path\to\test-repo --env-file .env --fail-model-call 2
```

首次运行应明确出现 injected failure，并保留 Run ID/checkpoint。随后：

```powershell
.\start.cmd resume <run_id> "D:\path\to\test-repo"
.\start.cmd replay <run_id> "D:\path\to\test-repo"
```

必须最终完成，Replay 中同时存在失败、恢复和成功验证证据。

### 真实模型评测

先跑一题确认配置：

```powershell
.\start.cmd eval3 1
```

成功生成报告后，再决定是否支付 20 题的时间和 Token：

```powershell
.\start.cmd eval3 20
```

报告位于 `.mini-code/evals/m3-*/report.json`。应包含模型、代码版本、Prompt 版本、日期、任务成功率、回归率、无关修改率、平均步骤、P50/P95、Token 和成本字段。成本未配置价格快照时允许为 `null`。建议项目投递底线：程序无崩溃、报告完整，Task Success Rate 不低于 60%；失败题必须保留 Trace 并如实分析。

## 4. M4：本地 Web Agent 控制台

### 安全启动

```powershell
.\start.cmd webdemo
```

它会创建一次性 workspace，然后启动：

```text
http://127.0.0.1:8765
```

在浏览器打开该地址，输入：

```text
修复 calculator.py 中除数为零时崩溃的问题，使 safe_divide 返回 None；检查实现和测试，完成修改、测试与 Diff 验证。
```

### 正常 Run 必须看到的证据

1. 创建后左侧出现 Run，详情显示同一个 Run ID；
2. 不刷新页面即可连续看到模型、工具、计划、Patch、测试和 checkpoint 事件；
3. 计划区状态随运行更新，同时最多一个 in_progress；
4. 变更区显示修改文件、测试次数和完成协议；
5. 指标区显示步骤、工具调用、耗时；API 返回 usage 时显示 Token；
6. 最终状态 completed，测试通过且完成协议为“已通过”；
7. 页面刷新后仍能恢复同一 Run 和历史事件，没有丢失已确认事件；
8. 左侧可以切换历史 Run。

### 取消验收

新建第二个任务，提交后尽快点击“取消运行”。模型请求正在传输时不会被强杀；响应结束后、下一工具执行前应进入 cancelled，并保存 checkpoint。关闭 Web 服务后可执行：

```powershell
.\start.cmd resume <run_id> "<Disposable M4 workspace>"
```

能继续完成则取消/恢复链路 PASS。

### M4 边界

- 必须只监听 `127.0.0.1`；`0.0.0.0` 会被拒绝；
- 浏览器不能指定或切换服务器 workspace；
- 当前无登录、多用户、远程部署和人工审批队列；
- 仓库测试仍以当前 Windows 用户权限运行，只在可信仓库或 Demo 中使用。

## 5. 最终验收记录模板

| 阶段 | 自动验收             | 人工日期 | Run/报告 | 结论      | 失败与备注 |
| ---- | -------------------- | -------- | -------- | --------- | ---------- |
| M1   | 37 tests OK          |          |          | PASS/FAIL |            |
| M2   | 37 tests OK          |          |          | PASS/FAIL |            |
| M3   | 37 tests + 15 probes |          |          | PASS/FAIL |            |
| M4   | 37 tests + HTTP/SSE  |          |          | PASS/FAIL |            |

只有对应阶段的“必须看到的证据”全部满足，才填 PASS。模型偶发失败可以重跑，但报告中应同时保留失败率，而不是只展示最好的一次。
